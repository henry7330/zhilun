# 04 · 写作

> **状态：⬜ 仅设计，未实现**（D2 需模型；D1/D3 的确定性部分可先做）
>
> 本文件是该阶段的**设计文档**：接口契约 + 各 Agent 的作用与「为什么需要」。

## 阶段目标

从「我有研究内容和数据」到「一份结构完整、表达规范的论文稿」。

## 输入 / 输出契约

| | 内容 |
|---|---|
| **输入** | `ResearchDesign` + `StatsResult` + `Library` + 学校模板 |
| **输出** | 论文草稿（Markdown，**能被 `copilot.quality.format.parse_markdown` 解析**） |
| **不做** | 不做格式检查（那是 E1）；不做重复率判断（那是 E3） |

**★ 输出格式必须是 Markdown** —— 因为下游 E1/E6 都基于
`parse_markdown` 产出的 `DocModel`。**契约在 D 阶段定，E 阶段才不会返工。**

## 三个 Agent

### D1 大纲生成 `OUTLINE`

| | 内容 |
|---|---|
| **作用** | 按学校 / 期刊要求产出章节大纲 |
| **输入** | 学校模板 + `ResearchDesign` |
| **输出** | `Outline`（章节树 + 每节要点） |
| **需模型** | 🟡 模板部分确定性，要点生成需模型 |

#### 为什么模板部分必须确定性

学校要求是**硬约束**（"必须有文献综述章""结论章不少于 500 字"）。
把硬约束交给模型 = 每次结果不同 = 有时漏章。

**做法**：章节骨架由模板**直接生成**，模型只负责"每一节写哪几个要点"。

#### 子部分

**① 模板骨架** —— 从 `Template.required_sections` 直接展开成章节树。
**② 要点分配** —— 把 `ResearchDesign.variables/baselines/metrics`
分配到对应章节（方法章放方法、实验章放基线）。
**③ 篇幅估计** —— 按模板字数下限分配每节目标字数。

**为什么需要篇幅分配**：不分配就会出现"绪论写了 5000 字，方法只有 300 字"——
这是学生论文最常见的结构失衡，E6 的 REV003 只能事后发现。

#### 接口

```python
def build_outline(
    design: ResearchDesign,
    *,
    template: Template | None = None,   # 缺省用 default_template()
    planner: Callable[[str], list[str]] | None = None,  # 缺省只出骨架
) -> Outline: ...
```

### D2 分章写作 `DRAFT`

| | 内容 |
|---|---|
| **作用** | 逐章生成正文 |
| **输入** | `Outline` 的一节 + 该节要用的证据 |
| **输出** | 该节正文（**每条论断带证据**） |
| **需模型** | ✅ 必须，**且必须走证据绑定** |

#### 为什么必须逐节而不是整篇

| 整篇生成 | 逐节生成 |
|---|---|
| 上下文太长，模型抓错重点 | 每节只带该节证据，焦点集中 |
| 一处出错整篇重来 | 只重写那一节 |
| 无法定位"哪句没依据" | 每节的 claim 可逐条校验 |

#### ★ 数据红线

**D2 不允许编造任何数字、实验条件、文献。**

这不是道德说教，是工程约束：一旦编造，
下游 E2 的 `verify_span` 会判 `fabricated`，整段被驳回 ——
**模型编造的东西在这里必须能拦住，否则整套系统失去意义。**

做法：把"可用证据"作为**唯一允许的素材**注入，
并在生成后跑 `verify_claim`，`fabricated` 的句子直接丢弃重写。

#### 子部分

**① 证据注入** —— 只把该节相关的 `EvidenceSpan` 放进上下文。
**② 生成 + 逐句绑定** —— 生成后立刻原子化 + 校验。
**③ 不达标重写** —— `unsupported` 比例超过阈值的整节重写（有重试上限）。

### D3 图表处理 `FIG`

| | 内容 |
|---|---|
| **作用** | 图表编号、交叉引用、题注规范 |
| **输入** | 草稿（含图表占位） |
| **输出** | 规范化后的草稿 + 图表清单 |
| **需模型** | ❌ **完全确定性** |

#### ★ 这一块已经实现了，只是位置在 E1

| 能力 | 现成实现 |
|---|---|
| 图表编号连续性检查 | `copilot.quality.format.rules.figures.check_figures` |
| 交叉引用是否断裂 | 同上（`FIG001` / `FIG002` / `FIG003`） |
| 题注格式（`图 1 xx`） | `copilot.quality.format.docmodel` 的题注识别 |
| LaTeX 图表环境生成 | `copilot.delivery.export.to_latex_skeleton` |

**所以 D3 不是"新写一套"，而是"把 E1 的检查反过来用作生成"** ——
这与 F3「反用质检报告」是同一个思路。

#### 接口

```python
def normalize_figures(doc: DocModel) -> tuple[DocModel, list[Finding]]: ...
```

**注意**：这个函数**会改内容**（重编号、修引用），
所以必须返回 `list[Finding]` 说明改了什么 —— **静默改用户文档是不可接受的**。

## 框架图

```
ResearchDesign + StatsResult + Library
              │
              ▼

              │
              ▼
        D2 逐节写作 ──▶ 草稿（每节带 claims）
              │            ↑
              │      copilot.evidence（逐句绑定 + 四态）
              ▼
        D3 图表规范 ──▶ 规范化草稿 + 改动清单
              │            ↑
              │      复用 E1 的图表规则（反向用作生成）
              ▼
        Markdown 草稿 ──▶ E 格式规整 / F 降重降AI
```

## 与后续阶段的关系：刻意**不**做闭环

```
04-writing 产出草稿
      │
      ├──▶ E 格式规整（按学校要求改文件 + 一致性 + 导出）
      └──▶ F 降重降AI（按外部报告改有问题的片段）
```

**这三个阶段彼此独立，串起来靠人，不靠流水线。**

**★ 但有一条纪律保留**：写作与检查必须是**两个独立环节**。

> 让模型自评自己的输出，会被自身的论证说服（LLM 的 sycophancy 问题）。
> 检查必须是**独立上下文**的另一个环节 —— 这就是 E/F 与 D 分开的意义。
>
> 具体体现：E 和 F **只读 D 产出的那篇草稿**，读不到 D 的内部状态，
> 因此它们无法"体谅"写作时的意图。

## 设计路线

| 步 | 内容 | 产出 | 状态 |
|---|---|---|---|
| 1 | 模板骨架展开 | `writing/outline.py` | 纯确定性 |
| 2 | 要点分配（规则映射） | 同上 | 纯确定性 |
| 3 | **D3 图表规范化**（反用 E1） | `writing/figures.py` | **最易先做** |
| 4 | 证据注入 + 逐节生成 | `writing/section.py` | 需模型 |
| 5 | 不达标重写循环 | 同上 | 需模型 |

**建议先做第 3 步**：纯确定性、复用现成规则、且能立刻验证"反用检查器做生成"这个思路。

## 验收标准

1. **大纲的必需章节与模板完全一致**（不漏、不多）；
2. **每节目标字数之和 ≥ 模板总字数下限**；
3. **D2 产出的每节都能被 `parse_markdown` 正确解析**（下游契约）；
4. **`fabricated` 的句子不得留在正文**；
5. **D3 改动必须留痕**（返回 `list[Finding]`，不能静默改）；
6. **重写有上限**（避免无限循环）；
7. **无模型时能只出骨架**，链路可跑通。

## 关键设计判断

| 判断 | 理由 |
|---|---|
| 输出必须是 Markdown | 下游 E1/E6 基于 `DocModel`，契约早定少返工 |
| 模板骨架确定性生成 | 硬约束交给模型 = 每次结果不同 |
| 逐节而非整篇 | 焦点集中、可局部重写、claim 可逐条校验 |
| D3 反用 E1 而非另写 | 同一件事只能有一份实现 |
| D3 改动必须留痕 | 静默改用户文档不可接受 |
| 写作与质检分离 | 模型自评会被自身论证说服 |

## 已知局限

| 局限 | 说明 |
|---|---|
| 生成质量取决于模型 | 骨架与校验是确定的，正文质量不是 |
| 要点分配是规则映射 | 复杂研究会分配不当，需人工调 |
| 逐节生成缺上下文连贯 | 章节衔接可能生硬，需要一次"过渡段"补写 |
| 图表只处理编号与引用 | 不生成图表内容（那是用户的数据可视化工作） |
| 篇幅控制只是目标值 | 实际字数由生成决定，偏差需事后调 |

# 第二部分：实现细节与实测

> 代码：`04-writing/src/copilot/writing/` · 测试：`04-writing/tests/test_writing.py`（15 项）
> 入口：`from copilot.writing import run_writing`

## 文件划分

```
src/copilot/writing/
├── models.py   OutlineSection / Outline / CaptionFact / FigureReport
├── outline.py  D1 模板骨架 + 要点分配 + 篇幅分配
├── figures.py  D3 图表分析 + 具体修复建议
└── __init__.py 节点装配 + run_writing
```

## ★ 节点顺序是 D1 → D3 → D2（不是 D1/D2/D3）

**先定结构，再查图表，最后写字。**

- 大纲没定就写正文 → 写完发现章节不对，全废；
- 图表放在正文之后查 → 正文改了图表位置，引用又乱了。

代码里的节点顺序按这个来，编号仍叫 D1/D2/D3（编号是功能标识，不是执行顺序）。

## D1 大纲生成 `outline.py`

**模板骨架必须确定性生成**：学校要求是硬约束，交给模型 = 每次结果不同 = 有时漏章。
所以骨架由 `Template.required_sections` 直接展开，模型只负责要点。

**要点由规则分配**（不是让模型随便想）：

| 设计里的东西 | 该出现在哪 |
|---|---|
| method / alternatives / variables | 方法章 |
| baselines / metrics / sample_size | 实验章 |
| risks | 讨论 / 局限 |

作用：让"研究设计写了什么"和"论文写了什么"**对得上** ——
这是写论文最常见的问题之一（设计了一套，写出来是另一套）。

**篇幅分配**按权重（摘要 0.6、方法 1.5、实验 1.6、结论 0.8…）。
不分配必然出现"绪论 5000 字、方法 300 字"，而 E6 的 REV003 只能事后发现。

## D3 图表规范 `figures.py`

**★ 只给建议、不自动改文件。** 这不是保守，是避免制造更严重的问题：

```
原文：  图 3 展示了框架。        ← 正文引用
        **图 3** 框架图          ← 题注

假设前面少了一个图，程序把题注重编号成 图 2
→ 正文里的「图 3」失去目标，引用断裂
```

**重编号题注而不动引用 = 把"编号不连续"换成"引用全是错的"。**
而引用分散在全文，自动改需要判断"这个数字指的是图还是页码/年份"，判错就改坏正文。

所以 D3 输出的是**精确到行**的建议：

```
第 7 行：图题注编号「图 2」→「图 1」（这是第 1 个图，按出现顺序应为 1）
第 5 行：图 5 引用「图 5」→「（需人工确认）」（全文没有编号为 5 的图，现有 [2,3]）
```

**只有题注编号不连续时才给具体替换值**（无歧义：题注是它自己的标签）。
引用不存在时只报，**不给替换值**。

### ★ 实测踩过的误报：按章编号

中文论文常用**按章编号**（图 2-1 / 图 3-1）。早期实现：

1. 把它当顺序编号参与重排 → 报"图 2 应为 图 1"（错）；
2. 引用正则只取到 `图 2-1` 里的 `2`，拿去跟题注比 → 判"图 3 未被引用"（错）。

修法：**一旦检测到按章编号，整体跳过顺序/引用存在性检查**。
理由是「宁可少报，不可误报」—— 这是本项目的统一取向。

## 实测结果

```
阶段 D：✅ 通过（3 个节点 / 错误 0 / 警告 3 / 提示 5）
输入草稿含「图 5 引用」+「图 2/图 3 题注」
  → D3 报 3 条：题注重编号 ×2 + 引用不存在 ×1
  → D2 只说 3 节"待写"（无生成器）
```

按章编号的草稿 → **D3 零发现**（正确跳过）。

## 已知局限（补充）

| 局限 | 说明 |
|---|---|
| D2 只有骨架 | 逐节生成 + 逐句证据绑定未接入模型 |
| 篇幅是目标值不是实测 | 生成后实际字数偏差需事后调（或由 E6 的 REV003 兜） |
| 要点分配靠章节名关键词 | 章节名不规范（如"我们的做法"）时分配不到要点 |
| 按章编号下不做图表检查 | 宁可少报 —— 这是刻意的取舍，不是遗漏 |
| D3 不检查图表内容 | 只查编号与引用，图里画得对不对管不了 |

# 第三部分：D4 文献引用（新增节点）

> 代码：`04-writing/src/copilot/writing/citations.py` · 测试：`04-writing/tests/test_citations.py`（14 项）
> 入口：`run_writing(..., entries=<B 阶段的文献库>)`

## 为什么要有这个节点

旧设计里"引用真实性"是**事后核查**（原 E2）：查 DOI 能不能解析、片段在不在原文。
那是**补漏** —— 成本高，而且查不全（你没法穷举所有可能的编造方式）。

现在的做法是**从源头约束**：

```
B 阶段（文献检索）已经核实过真实性 → 文献库里的每一篇都可信
        ↓  把文献库作为显式输入传给 D 阶段
D4 只做一件事：**正文引用的每一篇，必须能在文献库里找到**
        ↓
        找不到 = 引用来路不明 = 直接报错
```

**这一关是纯确定性的**（按 DOI / 规范化标题比对），不需要模型，也花不了钱。

## 三态判定：为什么不是两态

| 情况 | 判定 | 为什么 |
|---|---|---|
| 正文引了，库里也有 | ✅ 通过 | 正常 |
| 正文引了，**库里没有** | ❌ 错误 | 来路不明 —— 这正是最容易出事的地方 |
| 库里有的，正文没引 | ℹ️ 提示 | 不算错，可能是"忘了引"，也可能只是背景文献 |

第三种**只提示不报错**：参考文献表里放几篇综述做背景是正常写法。

## 实现要点

### ① 匹配用"全部身份标识"，不是单键

```python
def _keys(entry) -> set[str]:
    keys = set()
    if entry.doi:
        keys.add(f"doi:{entry.doi.lower()}")
    if normalize_title(entry.title):
        keys.add(f"title:{normalize_title(entry.title)}")
    return keys
```

**为什么不能只用 DOI**：库里的条目有 DOI，但正文的参考文献常常只有标题
（学生手写的参考文献表不一定带 DOI）。单键匹配会大面积报"库里没有"，那是误报。

**为什么不能只用标题**：同名论文真实存在（不同年份、不同团队撞名）。

所以：**两个键都算，命中任意一个即视为同一篇。**

### ② 从参考文献原文里捞 DOI

`Reference` 模型本身没有 `doi` 字段，所以从 `ref.raw` 里用正则捞：

```python
DOI_IN_RAW = re.compile(r"10\.\d{4,9}/[^\s,;，；]+")
```

**注意前缀位数的下限**：真实 DOI 的注册者代码是 4–9 位数字。
写测试时用 `10.1/x` 这种假 DOI 会**匹配不上**（我踩过，见下）。

### ③ 正文引用标注与参考文献条数对账

```python
numbers = {int(n) for grp in CITATION_MARK.findall(doc.body_text) for n in re.findall(r"\d+", grp)}
orphan = [n for n in numbers if n > len(doc.references)]
```

注意用 `doc.body_text` 而**不是全文** —— 参考文献区自己就带 `[1] [2]`，
拿全文去匹配会把每一条参考文献都当成"正文引用"。

## 实测结果

```
输入：3 条参考文献，其中 1 条在文献库里
D4 ok=True stats={'references': 3, 'matched': 1, 'library': 1}

参考文献 1 条，库内匹配 1 条                  ← 正常
第 [1] 条不在文献库：李四. 另一篇来路不明的文章  ← 错误，报告判为不可通过
文献库里这些没被引用：王五. 没人引用的综述        ← 提示，不算错
```

## 踩过的坑

| 现象 | 根因 | 教训 |
|---|---|---|
| `[5]` 引用了但没报错 | 我把测试里的 `[5]` 追加在**参考文献区之后**，而 `body_text` 不含参考文献区 | 测"正文引用"要确认它真的在正文里 |
| DOI 匹配失败 | 测试用了假 DOI `10.1/x`，不满足 `10\.\d{4,9}/` | **测试数据要符合真实格式**，否则测的是正则的边界而不是逻辑 |
| `d4.ok` 为 True 但有 ERROR | `NodeResult.ok` 表示"节点没跑崩"，不是"检查通过" | 两个语义要分开断言：`d4.ok` + `report.can_submit` |

## 已知局限

| 局限 | 说明 |
|---|---|
| 标题匹配对"同一篇的不同译名"无效 | 「Retrieval-Augmented Generation」与「检索增强生成」是两个键 |
| 不检查引用位置是否恰当 | 只查"在不在库里"，不查"引在这里对不对" |
| 预印本与正式版算两篇 | DOI 不同即视为不同文献 |
| 没有文献库时只警告不报错 | 因为那是"没法核对"，不是"引用错了" |
