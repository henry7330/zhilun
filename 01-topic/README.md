# 01 · 选题与开题

> **状态：⬜ 仅设计，未实现**（需要模型；且下游阶段尚未就绪）
>
> 本文件是该阶段的**设计文档**：接口契约 + 各 Agent 的作用与「为什么需要」。
> 实现时按「设计路线」逐步落地，并把实测结果与踩过的坑补进本文件。

## 阶段目标

把「不知道写什么」变成「**一个可执行的研究题目 + 一份开题报告**」。

## 为什么这个阶段排在最前

它的产出**约束后面所有阶段**：

```
题目定不下来 → 文献检索没有方向 → 研究方法无从设计 → 写作没有主线
```

**但这也是最容易"空转"的阶段**：很多选题工具只会给出"XX 领域有前景"这类
无法执行的话。本阶段的验收标准专门防这一点。

## 输入 / 输出契约

| | 内容 |
|---|---|
| **输入** | ① 领域语料（论文标题 / 摘要集合）② 用户条件（数据可得性、时间、技术栈） |
| **输出** | `TopicSpec`：题目 + 关键词 + 研究问题 + 研究空白清单 |
| **不做** | 不替用户决定"应该研究什么"（那是导师的职责）；不承诺工作量 |

### 向下游传递的数据

```python
TopicSpec = {
    "title": str,              # 最终题目
    "keywords": list[str],     # 3–8 个，供 B1 检索用
    "questions": list[str],    # 2–4 个研究问题，供 C1 方法设计用
    "gaps": list[Gap],         # 研究空白，每条带支撑语料
    "feasibility": dict,       # A2 的结论
}

Gap = {
    "text": str,               # "现有工作在长尾查询上覆盖不足"
    "support": list[str],      # 支撑它的论文 doc_id（**必须有**）
    "strength": str,           # "explicit"（原文说了）| "inferred"（模型归纳）
}
```

**★ `Gap` 必须带 `support`** —— 一个没有任何语料支撑的"研究空白"是猜测。
这与 B2 综述、D2 写作走同一套证据绑定规则（见 `copilot.evidence`）。

## 三个 Agent

### A1 选题分析 `TOPIC`

| | 内容 |
|---|---|
| **作用** | 从领域语料里挖关键词共现、时间趋势、研究空白 |
| **需要什么** | `Sequence[Document]`（语料） |
| **输出** | `TopicSignals`：`{keywords, trends, gaps}` |
| **需模型** | ❌ 不需要（统计部分完全确定） |

#### 三个子部分

**① 关键词共现** —— 统计语料里哪些术语经常一起出现。

**为什么需要**：共现强的两个词往往构成一个成熟子领域；
共现弱但各自高频的两个词，**交叉处常常就是空白**。

**② 时间趋势** —— 按年份统计关键词热度。

**为什么需要**：区分"已经做烂了"和"刚起来"。一个关键词连续五年占比下降，
说明这个方向在退潮 —— 选题前知道这件事能省半年。

**③ 研究空白候选** —— 用「高频关键词 × 低覆盖组合」找候选空白。

**为什么需要**：这是 A1 唯一有价值的部分。但必须标 `strength="inferred"` ——
**统计出来的"空白"只是候选，不是结论**。

#### 接口

```python
def analyze_topic(
    documents: Sequence[Document],
    *,
    top_k: int = 20,
    min_support: int = 2,
) -> TopicSignals: ...
```

#### 复用

| 复用什么 | 来源 |
|---|---|
| 语料加载 | `copilot.retrieval.corpus`（`load_corpus` / `documents_from_corpus`） |
| 分词口径 | `copilot.evidence.text.tokenize` / `content_tokens` |
| 趋势的统计检验 | `copilot.stats`（若需判断"趋势是否显著"） |

---

### A2 可行性评估 `FEAS`

| | 内容 |
|---|---|
| **作用** | 判断数据可得性、工作量、技术难度 |
| **输入** | `title` + 用户条件（时间、数据、技术栈） |
| **输出** | `Feasibility = {level, blockers, risks, suggestions}` |
| **需模型** | ✅ **必须**（这是判断，不是计算） |

#### 为什么不能确定性实现

"这个题目三个月做得完吗"没有任何可计算的定义。
即使强行写成规则，规则本身也是拍脑袋 —— **那比承认需要模型更糟**，
因为它会把主观判断伪装成客观结论。

#### 三个子部分

**① 数据可得性** —— 题目需要什么数据？用户有没有？
**② 工作量拆分** —— 拆成"数据准备 / 方法实现 / 实验 / 写作"四块，各给量级。
**③ 前置风险** —— 哪些假设一旦不成立，题目就要推倒。

**★ 设计要点：必须输出 `blockers`（阻断性风险），而不是只给总评。**

> "可行性中等"这种结论**没有决策价值**；
> "需要标注 1 万条数据，你手上没有"才有。

### A3 开题报告生成 `PROPOSAL`

| | 内容 |
|---|---|
| **作用** | 产出结构化开题报告 |
| **输入** | `TopicSpec` + 文献片段 |
| **输出** | `Proposal`（研究背景 / 意义 / 现状 / 内容 / 方法 / 进度） |
| **需模型** | ✅ 必须，**且必须走证据绑定** |

#### 为什么必须走证据绑定

开题报告的"国内外研究现状"一节**天然是引用密集区**。
不绑定证据，模型会编造文献 —— 这正是本系统存在的第一理由。

**做法**（这套流程 `copilot.evidence` 已全部实现，A3 只需调用）：

```
生成句子 → 原子化成 claim → bind_evidence 找候选原文
        → verify_span 三重校验 → verify_claim 判四态
        → 只有 supported / partially_supported 才输出
```

#### 接口

```python
def generate_proposal(
    topic: TopicSpec,
    *,
    generator: Callable[[str, str], str] | None = None,   # 缺省 = 无模型
    doc_store: DocStore,
    binder: EvidenceBinder | None = None,
) -> Proposal: ...
```

**`generator=None` 时只产出章节骨架 + 待填标记** ——
"没模型也能跑通链路"这条纪律在本阶段同样成立。

## 设计路线

| 步 | 内容 | 产出 |
|---|---|---|
| 1 | 语料统计：共现 / 趋势 | `topic/signals.py` |
| 2 | 空白候选（**标 inferred**） | 同上 |
| 3 | `TopicSpec` 组装与校验 | `topic/models.py` |
| 4 | 可行性评估（模型，缺省给骨架） | `topic/feasibility.py` |
| 5 | 开题报告生成（走证据绑定） | `topic/proposal.py` |

## 验收标准

1. **共现与趋势是真实统计**：给定语料，任何人重跑得到同一数字；
2. **空白候选必须带 `support`**；`support` 为空的候选**不输出**；
3. **`strength` 标注准确**：模型归纳的必须标 `inferred`，不得冒充 `explicit`；
4. **可行性必须给 `blockers`**，不能只给总评；
5. **无模型时链路可跑通**（只出骨架 + 待填标记）；
6. **`TopicSpec` 通过 schema 校验**（keywords 3–8 个、questions 非空）。

## 关键设计判断

| 判断 | 理由 |
|---|---|
| 空白候选必须带 `support` | 没有语料支撑的"空白"是猜测，会误导整篇论文 |
| `strength` 区分 explicit / inferred | 原文说了 vs 我归纳的，可信度差一个数量级 |
| 可行性必须给 `blockers` | 总评无法决策 |
| 无模型也出骨架 | 保持"链路先跑通"的纪律，与 F 阶段一致 |
| 不替用户选题 | 选题是学术判断，工具只提供信号 |

## 已知局限

| 局限 | 说明 |
|---|---|
| **空白检测只是候选** | "低频组合"不等于"真空白"，可能只是没人觉得值得做 |
| 趋势受语料偏差影响 | 只抓某个数据库 → 得到的是该库的趋势，不是领域的 |
| 可行性依赖模型判断 | 无法验证；只能靠"给 blockers 而非总评"降低误导 |
| 不覆盖跨学科题目 | 语料按单一领域组织时，跨学科组合会被判为低频 |
| 进度规划不可执行 | 模型给的时间估计没有依据，只能当参考 |

## 各节点的实现要点

### A1 选题分析 `signals.py`

**全部确定性**：同一份语料重跑得到完全一样的词表与计数。

| 子部分 | 实现 | 产出 |
|---|---|---|
| 关键词 | `content_tokens` + 停用词过滤 | 词频表 |
| 共现 | 同篇内两两组合计数 | 高频对（成熟子领域） |
| 趋势 | 按 `years` 分年计数 | 逐年热度 |
| 空白候选 | 「高频 × 零共现」 | `Gap`（全部 `inferred`） |

**★ 两个实测踩过的 bug**：

**① 共现键顺序不一致 → 假空白（严重）**

共现表按**字母序**存 key（`sorted(present)`），而查表用的是**词频序**的
`frequent` 列表。两边顺序不同 → `pair_lookup.get((a, b))` 恒返回 0
→ **把明明同篇出现过的词对报成"从未同篇出现"**。

实测：「推荐」与「应用」在第一篇里同时出现，却被报成空白候选。

修法：查表与存表统一成字母序 `tuple(sorted((a, b)))`。

**② 中文二字组跨词 → 术语表全是噪声**

`content_tokens` 产出的是**字面二字组**，会把「检索增强」切成
检索 / 索增 / 增强 —— 中间那个 `索增` 是跨词噪声。

修法：① 扩充停用词（含「中的」「对于」这类虚词二字组）；
② 用中文虚词字符表过滤含虚词的组合。

**但去不干净**（`索增` 两个字都是实字）。所以 README 里必须写明：
**关键词是"候选"，不是"领域术语表"**。真要准确得接分词器或让模型归纳。

**③ 小语料必须警告**：`len(texts) < 20` 时追加一条 note，
说明"空白候选噪声很大，大概率是语料不足而非真有空白"。

### A2 可行性 `agents.py`

**没模型时给"该问的问题"，不编造 level。**

```
level = "unknown"
blockers = ["未接入模型，无法评估可行性 —— 下面是该自己回答的问题"]
risks = [
    "数据是否真的能拿到？注意区分「确实有」和「网上应该有」",
    "最耗时的一步是什么？大概需要多久？",
    "如果核心假设不成立，这个题目还能不能做？",
]
```

**有模型时若 blockers 为空，反而报 WARNING**：

> 「没有阻断性风险」通常意味着评估不到位 —— 任何研究都有前置假设。

### A3 开题报告 `agents.py`

六节骨架（背景/现状/内容/方法/进度/成果），每节给写作要点。
「研究现状」那节的要点里明确写了 **每条陈述都要能落到具体文献**。

`python 05-format/examples/demo_all_stages.py` 的 A 段：

```
阶段 A：✅ 通过（无阻断项）（3 个节点 / 错误 0 / 警告 1 / 提示 7）
  ✅ A1 统计 6 篇语料，取前 20 个关键词；空白候选 5 条（均标 inferred）
  ✅ A2 骨架模式（给出 3 个该回答的问题）
  ✅ A3 未接入模型 —— 章节骨架
```

## 已知局限（补充）

| 局限 | 说明 |
|---|---|
| **关键词是字面二字组** | 没有分词器，跨词噪声无法根除（`索增`/`图神` 这类） |
| 空白候选在 6 篇语料上不可信 | 已加警告，但**不会阻止输出** —— 因为拦掉就什么都不剩了 |
| 趋势需要外部给年份 | `Document` 里没有年份字段，靠调用方传 `years` |
| A2/A3 的骨架不算完成品 | 阶段报告会明确标 `skeleton=True`，但 A 阶段整体仍可能判"通过" |
