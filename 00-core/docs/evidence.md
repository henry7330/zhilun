## 本模块解决的核心问题

> **论文助手最致命的失败模式，是编造一篇不存在的文献，
> 或引用原文里根本没有的话。**

如果不建设这一层，"模型说了什么"与"原文写了什么"之间
**没有任何强制的对应关系** —— 你无法回答"这条结论依据是什么"，
也无法测量"编造引用率"这个指标。

# 第一部分：设计

## 框架图

```
模型生成的一段文字
        │
        ▼
┌──────────────────┐
│ ③ 断言原子化       │  把整段拆成**可独立判断真伪**的最小单元
│   extract.py     │  「该结论具有理论意义」这类无法验证的先剔除
└────────┬─────────┘
         ▼
┌──────────────────┐
│ ④ 证据绑定         │  为每条断言在文献中找**讲同一件事**的原文片段
│   bind.py        │  ⚠️ 只判「相关性」，**不判一致性**
└────────┬─────────┘
         ▼
┌──────────────────────────────┐
│ ⑤ 一致性校验   verify.py      │
│   三重校验：文档存在 → hash 未变 → 偏移处文字相符
│   引用校验：DOI 可解析 → 文献库匹配 → 年份核对
└────────┬─────────────────────┘
         ▼
┌──────────────────────────────┐
│ ⑥ 支持程度判断  support.py    │
│   ① 极性矛盾 → FABRICATED                  │
│   ② 数字缺失 → PARTIALLY_SUPPORTED          │
│   ③ 覆盖率不足 → UNSUPPORTED                │
└────────┬─────────────────────┘
         ▼
    四态结论 + 证据出处（可回溯到字符偏移）
```

## 三条关键设计判断

### 判断一：「编造」与「信息不足」必须分成四态

| 状态 | 含义 | 对用户的意义 |
|---|---|---|
| `supported` | 证据明确支持 | 正常输出 |
| `partially_supported` | 部分支持 | 标注不确定性 |
| `unsupported` | **找不到证据** | **提示补充检索** |
| `fabricated` | **与证据矛盾 / 引用不存在** | **告警** |

**为什么不能合成一个布尔**：如果只有"不可信"，
系统会对普通的信息不足过度反应，同时**削弱真正编造信号的严重性**。

### 判断二：绑定层只判「相关性」，不判「一致性」

`RuleBinder` 只回答"这段原文是不是在讲同一件事"（用词汇覆盖率），
**不判断它支持还是反对**。

**为什么**：如果绑定阶段就把矛盾的证据丢掉，
那"结论与原文相矛盾"这个**最强的幻觉信号**就永远触发不了，
只会退化成含糊的"没找到证据"。

### 判断三：很大一部分"支持判断"不需要模型

这是本项目做下来**推翻原计划**的发现。原计划把"证据是否支持结论"
整块划给语义层（需要模型）。实际发现两类矛盾是**确定性可判**的：

- **极性**：结论说"提升"、原文说"下降"
- **数字**：声称"5%"、原文没有 5%

带来两个后果：得到一个**零成本可复现的基线**
（否则"模型比规则好多少"无法回答）；大量明显矛盾无需调用模型。

## 设计路线

| 步 | 内容 | 产出 |
|---|---|---|
| 1 | 数据模型与四态 | `models.py` |
| 2 | 文本特征（分词/数字/极性轴） | `text.py` |
| 3 | 断言原子化（规则基线） | `extract.py` |
| 4 | 证据绑定 | `bind.py` |
| 5 | 三重一致性 + 引用真实性 | `verify.py` |
| 6 | 支持程度判断 | `support.py` |
| 7 | 端到端演示 | `examples/demo_evidence_guard.py` |

## 验收标准

1. 编造的引用（DOI 不存在 / 文献库无此条）→ **必须被判为 fabricated**；
2. 文档被替换后，旧片段 → **必须报 `HASH_MISMATCH`**，而不是静默通过；
3. 矛盾证据 → **必须仍被绑定**（否则最强的幻觉信号丢失）；
4. 信息不足 → **判 `unsupported` 而非 `fabricated`**（四态不可混）。

# 第二部分：实现细节

## ① 数据模型与四态 `models.py`

```python
class SupportStatus(str, Enum):
    SUPPORTED = "supported"
    PARTIALLY_SUPPORTED = "partially_supported"
    UNSUPPORTED = "unsupported"
    FABRICATED = "fabricated"
```

`EvidenceSpan` 有一个**强制校验**：

```python
def __post_init__(self):
    if self.char_end - self.char_start != len(self.text):
        raise ValueError(...)
```

**为什么强制**：偏移量与文本必须自洽，否则"三重校验"里的第三步
（`doc.content[start:end] == span.text`）就永远查不出问题 ——
因为两者本来就对不上，错误会被掩盖成"文本不符"而不是"数据构造有误"。

## ② 文本特征 `text.py`

两种分词口径，**用途不同**：

```python
def tokenize(text)      # 保留重复 —— 给 BM25 用（词频有意义）
def content_tokens(t)   # 去重集合 —— 给覆盖率用（重复不增加覆盖）
```

**极性冲突检测用「语义轴」而不是简单反义词表**：

```python
ANTONYM_AXES = {
    "升降": (("提升","提高","增加",...), ("下降","降低","减少",...)),
    "好坏": (("改善","优化","有效",...), ("恶化","变差","失效",...)),
    "立场": (("支持","赞成",...), ("反对","质疑",...)),
}
```

**为什么用轴**：早期写成两两配对的 antonym 表，漏掉了 (降低, 上升) 这一对。
改成轴之后，**同轴内任意正词与任意负词都算冲突**，不再依赖手工穷举配对。

同时加了一道**保护**：跳过"自身内部就混合了正负词"的断言 ——
那种句子本身在讲对比（"X 提升了，Y 下降了"），不该判为矛盾。

## ③ 断言原子化 `extract.py`

```python
MIN_FRAGMENT_CHARS = 4
_CLAUSE_SPLIT      # 切分子句的连接词，刻意**排除「和」「与」**
```

**为什么 `MIN_FRAGMENT_CHARS` 是 4 而不是 6**：
初版设 6，导致「降低了延迟」这 5 字断言被丢掉。
中文信息密度高，**用英文长度阈值会系统性丢弃中文短断言**。

**为什么排除「和」「与」**：「A 和 B 都提升了」拆开会丢掉主谓关系，
产出两个语义不完整的碎片，反而制造误报。

## ④ 证据绑定 `bind.py`

```python
class RuleBinder:
    def __init__(self, min_relevance: float = 0.5, max_spans: int = 2): ...
```

**核心设计**：**宁可少绑定，不可绑错**。低于阈值就留空，
让下游判为 `unsupported`（信息不足），而不是硬塞一段不相关的原文
制造一个假的 `supported`。

绑定阈值在样例里实测有效：相关性 0.23 的片段被拒绝，
输出「最高相关性仅 0.23，低于绑定阈值；按『宁可少绑定，不可绑错』处理」。

## ⑤ 一致性校验 `verify.py`

**三重校验**：

```python
doc = doc_store.get(span.doc_id)
if doc is None:                      # ① 文档在不在
    return SpanProblem.DOC_NOT_FOUND
if doc.content_hash != span.source_hash:   # ② 文档变没变
    return SpanProblem.HASH_MISMATCH
actual = doc.content[span.char_start:span.char_end]
if actual != span.text:              # ③ 这个位置的文字对不对
    return SpanProblem.TEXT_MISMATCH
```

**为什么第 ② 步不可省**（哪怕第 ③ 步也在比对文字）：

hash 绑定的是**文档版本**，不只是内容。文档被替换后，
即使新文档在相同偏移处恰好有相同文字，这段证据也已经**过期**了 ——
结论是从**旧版本**推导出来的。第 ③ 步查的是"这个位置的文字对不对"，
第 ② 步查的是"这还是不是当初那份文档"。

**引用真实性校验**：

```python
class CitationProblem(str, Enum):
    OK
    NO_IDENTIFIER        # 既无 DOI 也无标题，无法核实
    DOI_NOT_RESOLVABLE   # DOI 解析不出来 → 大概率是编造的
    NOT_IN_LIBRARY       # 文献库里没有
    YEAR_MISMATCH        # 年份对不上
```

## ⑥ 支持程度判断 `support.py`

```python
class RuleBasedJudge:
    def __init__(self, supported_threshold=0.70, partial_threshold=0.35): ...
```

判定优先级（顺序有意义）：

1. **极性冲突 → FABRICATED**（最高优先：矛盾比缺失严重得多）
2. **断言里有数字但证据里没有 → 降级为 PARTIALLY_SUPPORTED**
3. **覆盖率 ≥ 0.70 → SUPPORTED**；≥ 0.35 → PARTIALLY；否则 UNSUPPORTED

# 第三部分：★ 规则方法的能力边界（实测）

本模块**如实记录了自己做不到什么**，这是刻意为之：

| 情况 | 词面结构 | 规则判定 | 对不对 |
|---|---|---|---|
| `decreased accuracy` vs `improved accuracy` | 好坏轴 vs 升降轴 | 无冲突 | ❌ **漏报**（真矛盾） |
| `decreased latency` vs `improved latency` | **完全同构** | 无冲突 | ✅ 正确（二者一致） |

**两句话在词面上完全同构，但一个是矛盾、一个是一致** ——
区别只在于「被修饰的指标是否越大越好」（accuracy 越大越好，latency 越小越好）。
这需要**世界知识**，纯词面方法拿不到。

**有意不加规则**：若把 `improve/decrease` 加成反义词，
第二句就会变成**误报** —— 用漏报换误报并不划算。

> 这条边界正是统计评测要量化的东西：**LLM 判断在这些跨轴案例上能补多少**。

# 第五部分：已知局限

| 局限 | 说明 |
|---|---|
| **跨轴极性判不出来** | 见第三部分，需要世界知识 |
| **不处理跨句推理** | "A 提升，B 下降，因此整体变好"这类需要多句合成的判断做不到 |
| **绑定靠词汇覆盖率** | 同义改写（"精度"vs"准确率"）会漏绑 |
| **参考文献库需外部提供** | `DocStore` / `CitationLibrary` 目前是内存实现，接真实库需另写适配器 |
| **无模型版本** | `LlmExtractor` / `LlmJudge` 尚未实现，因此"规则 vs 模型"的对比实验还没跑 |
