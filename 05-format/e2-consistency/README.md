# E6 · 审稿挑错

> 状态：**待做**（结构检查可确定性实现，语义部分需模型）
> 计划代码位置：`05-format/e2-consistency/src/copilot/quality/review/`

## 本模块解决的核心问题

> **论文的结构与逻辑有没有明显问题？** —— 相当于一个"初审意见"。

写完之后作者自己最难发现问题，因为**你知道自己想说什么，
所以会自动补全没写出来的部分**。机器没有这个补全，反而能看出断裂。

## 与相邻模块的分工

E4/E5 处理的是"**外部报告指出的问题**"（重复、疑似 AI），
E6 处理的是"**报告没提、但结构与逻辑上的问题**" —— 两者不重叠：

| | E3/E4/E5 | E6 |
|---|---|---|
| 问题来源 | 外部检测报告 | **系统自己看整篇文档** |
| 关注点 | 文字层面（重复、风格） | **结构与逻辑层面** |
| 是否需模型 | 改写需模型 | **一半可确定性实现** |

## 层级定位

```
src/copilot/quality/review/          ← 本包
        ├── 子部分 1  结构完整性检查        ★ 确定性
        ├── 子部分 2  图表引用一致性        ★ 确定性（复用 E1）
        ├── 子部分 3  术语一致性            ★ 确定性
        ├── 子部分 4  论证链断裂检测        （需模型）
        └── 子部分 5  审稿意见报告
```

## 各子部分的初步设计意图

| 子部分 | 作用 | 为什么需要 |
|---|---|---|
| **① 结构完整性检查** | 每章是否有引言与小结；"提出问题"后是否有"解决问题" | 是**可判定的结构模式**。论文最常见的结构缺陷就是"提了问题但正文没回应" |
| **② 图表引用一致性** | 正文提到的图表、章节、公式是否存在 | **复用 E1 的 `figures.py`** —— 同一能力，不同触发入口 |
| **③ 术语一致性** | 同一个概念是否用了多个叫法（"准确率/精度/正确率"混用） | **完全可判定**，而且人工几乎不可能全文核对 |
| **④ 论证链断裂检测** | "因此""所以"前面是否有支撑；结论是否超出实验范围 | 需模型（跨句推理） |
| **⑤ 审稿意见报告** | 按章节组织的意见清单，分级 | 与 E1 的报告同构，可复用报告基础设施 |

## 关键设计判断（预告）

| 判断 | 理由 |
|---|---|
| **先做确定性的一半** | 结构/引用/术语一致性都能规则判定，这部分先做扎实；论证链再做模型版 |
| **复用 E1 的图表检查** | 同一个能力不该实现两遍；E1 是"格式视角"，E6 是"内容视角"，共用引擎 |
| **"挑错"不等于"评价"** | 只指出可验证的问题（结构缺失、术语不一致），不给"这篇论文好不好"的主观评分 |
| **意见要能定位** | 与 E1 同理：定位到章节/行，否则作者不知道去哪改 |

## 与其它模块的关系

| 模块 | 关系 |
|---|---|
| **E1 格式校验** | 复用其文档模型（章节树、图表题注、交叉引用）与报告基础设施 |
| **E2 引用真实性** | 互补：E2 查"引用是否真实"，E6 查"该引用的地方有没有引用" |
| **E5 降AI** | 术语一致性的文本特征提取可复用其 `features.py` |

# 第二部分：实现细节

## 与 E1 的复用边界

```
从 E1 直接拿来用：
  parse_markdown       文档解析（章节树、图表题注、交叉引用）
  Issue / Severity     问题词汇
  check_figures        图表引用检查
  DocModel.flat_sections()  章节展开
```

**为什么必须复用**：同一件事只能有一份实现。两份解析器迟早会不一致，
而那种不一致**极难发现** —— 这与 E3/E4 共用引用判定是同一个理由。

**副作用（好的）**：因为共用 `Issue` 词汇，E6 的审稿意见可以和
E1 的格式问题**直接合并成一份质检报告**，不需要任何格式转换。

## ① 术语一致性 `check_terms`

```python
SYNONYM_GROUPS = (
    ("召回率", "查全率"),
    ("精确率", "查准率"),
    ("准确率", "正确率"),
    ("鲁棒性", "健壮性"),
    ...
)
```

判据：同一组里有 **≥ 2 个**词在正文出现 → 报 `REV001`。

**★ 刻意不收「准确率 / 精确率」**：在信息检索里这是**两个不同指标**
（precision vs accuracy），混成一组会误报。

**只报 WARNING，不判对错**：作者可能是有意区分（比如在某一节明确定义过）。
机器不该替他决定 —— 所以建议写的是「确认是否需要统一」。

## ② 关键词覆盖 `check_keywords`

```python
KEYWORD_LINE = re.compile(r"^\s*(?:\*\*)?\s*关键词\s*(?:\*\*)?\s*[:：]\s*(.+)$", re.MULTILINE)
```

从摘要里抽关键词，检查每个词在**正文（去掉摘要部分）**里是否出现。

**为什么要去掉摘要**：关键词本来就是在摘要里写的，
如果不去掉，"关键词"会自己命中自己，检查永远通过。

**这条检查抓的是"摘要与正文脱节"** —— 摘要承诺了某个主题，
正文里却一次都没讨论。审稿人很常提这个问题，但作者自己很难发现
（因为摘要和正文通常是分开写的）。

## ③ 章节篇幅 `check_section_length`

```python
SHORT_SECTION_CHARS = 120
_LENGTH_EXEMPT_TITLES = {"参考文献", "致谢", "摘要", "abstract", ...}
```

**只报一级章节**：小节的篇幅本来就短，对小节设阈值只会制造噪声。

**★ 必须豁免参考文献/致谢/摘要**（实测踩过）：
这几类章节**本来就短**（参考文献是条目列表、致谢是礼节文字、
摘要有独立字数上限）。对它们套用"论述不充分"的判断，
会让每份文档都刷出一堆无意义提示 —— 用户就不看报告了。

## ④ 图表引用 `check_figure_refs`

```python
def check_figure_refs(doc, template):
    return check_figures(doc, template)     # ← 直接转调 E1
```

E1 是"格式视角"（编号规范不规范），E6 是"内容视角"（引用有没有断），
但**判定逻辑完全相同**，所以直接转调。

## 这些检查为什么值得自动化

| 检查 | 人工为什么难 |
|---|---|
| **术语不一致** | 全文搜一遍才知道；读到后面早就忘了前面怎么写的 |
| **关键词脱节** | 摘要与正文分开写，二者对不上自己很难发现 |
| **图表引用断裂** | 增删图表后最容易漏改，需要通读全文 |
| **章节过短** | 字数统计一下就知道，但很少有人会去数 |

# 第四部分：已知局限

| 局限 | 说明 |
|---|---|
| **不检查论证逻辑** ★ | 需要跨句语义理解，属模型范畴。**报告里明确写了这一点** |
| **同义词表是手工维护的** | 只收了「大多数学科内视为同义」的组，覆盖有限 |
| **不判断术语用法是否恰当** | 只查"是否一致"，不查"用得对不对" |
| **章节篇幅阈值是经验值** | 120 字无数据支撑；不同学科差异很大，可通过 `min_section_chars` 调 |
| **关键词检查依赖标准格式** | 只认「关键词：」这一行；非标准写法识别不到 |
| **不做主观评价** | 「挑错」不等于「打分」：只指可验证的问题，不给"这篇论文好不好" |

# 第五部分：★ 一个只有建评测集才会发现的 bug

## 现象

建标注评测集时，有一条用例：**「结论」正文只有 5 个字，期望报 REV003**。
跑下来**什么都没报**。

单测全绿 —— 因为单测夹具都用 `# 章节` 的写法。

## 根因：两种论文写法，光看层级分不出来

```
写法 A（单测用的）        写法 B（真实论文常见）
# 摘要                    # 论文题目
正文…                     ## 摘要
# 结论                    正文…
正文…                     ## 结论
                          正文…
```

`check_section_length` 早期实现是：

```python
for s in doc.sections:      # 只看顶层
```

- 写法 A：顶层就是章 → 检查正常 ✓
- **写法 B：顶层只有"论文题目"一个节点，章节全在第二层 → 检查被完全跳过** ✗

而且**不报错、不提示** —— 看起来像"这篇论文篇幅都合格"。
**静默失效是最糟的一种失败。**

## 第一次修：按节点数量判断（不够）

第一版修法是"顶层只有 1 个节点时下沉一层"。但 `# 一` + `## 一点一` + `## 一点二`
也是"顶层只有 1 个节点" —— 此时下游是**小节**，不该被篇幅检查。

这条修正立刻把一条旧测试打挂了（`test_subsection_length_not_checked`），
正好说明**启发式太粗**。

## 最终修法：用「章节名知识」判别，而不是层级数量

```python
def _resolve_chapter_level(doc, template):
    sections = doc.sections
    if len(sections) != 1 or not sections[0].children:
        return sections

    top = sections[0]
    # 顶层自己就是章节名（如 `# 摘要`）→ 顶层是章
    if is_chapter_name(top.title):
        return sections
    # 子节点有章节名而顶层没有 → 顶层是文档题目，下沉一层
    if any(is_chapter_name(c.title) for c in children):
        return list(children)
    return sections
```

`is_chapter_name` 查两处：`COMMON_SECTION_NAMES`（常见章节名词表）+ 模板的必需章节。

**两种写法都对**：

| 结构 | 判定 | 检查对象 |
|---|---|---|
| `# 摘要` + `# 结论` | 顶层多个节点 | 顶层 ✓ |
| `# 论文题目` + `## 摘要` … | 顶层非章节名，子节点是 | **子节点** ✓ |
| `# 一` + `## 一点一` … | 顶层非章节名，子节点也不是 | 顶层 ✓ |

## 教训

> **单元测试证明"代码按设计跑"，不证明"检得准"。**
>
> 这条 bug 在设计、实现、单测、演示四个环节都没暴露 ——
> 因为**它们用的都是同一种文档写法**。只有"换一种真实写法并给出标准答案"
> 的评测集才照出了它。

这也是为什么 `eval/run_agent_eval.py` 值得存在：
**它不是重复单测，它换了一个提问方式。**
