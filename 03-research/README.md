# 03 · 研究

> **状态：⬜ 仅设计，未实现**（C1 需模型；C2 的统计工具已就绪，缺 Agent 外壳）
>
> 本文件是该阶段的**设计文档**：接口契约 + 各 Agent 的作用与「为什么需要」。

## 阶段目标

从「我要用方法 M 解决问题 P」到「一套**可执行**的研究设计与数据分析方案」。

## 为什么这个阶段最容易出事

这里最容易出现**方法论上的自欺**：

| 自欺形式 | 表现 |
|---|---|
| 没有对照组 | "A 比 B 好"其实只是 A 跑在更容易的样本上 |
| 统计检验误用 | 用独立 CI 比较配对数据（本项目**真的踩过**） |
| 把噪声当效应 | 15 次比较里挑出"显著"的那次报上去 |
| 指标选错 | 类别不平衡时只看准确率 |

**本阶段的全部设计都围绕一件事：让"结论"必须附带能反驳它的证据。**

## 输入 / 输出契约

| | 内容 |
|---|---|
| **输入** | `TopicSpec.questions` + `Library` + 实验数据（用户提供） |
| **输出** | `ResearchDesign` + `StatsResult` |
| **不做** | 不替用户跑实验；不生成实验数据（**编造数据是红线**） |

### 向下游传递的数据

```python
ResearchDesign = {
    "method": str,                  # 技术路线
    "alternatives": list[str],      # 比选过的其他路线 + 为什么没选
    "variables": {"independent": [...], "dependent": [...], "controlled": [...]},
    "baselines": list[str],         # **必须有**，否则结论不成立
    "sample_size": {"n": int, "justification": str},
    "metrics": list[Metric],        # 每个指标要说明衡量什么
    "risks": list[str],             # 设计层面的风险
}

StatsResult = {
    "comparisons": list[Comparison],  # 每次比较：两组、差值 CI、p、效应量
    "corrections": {"method": "BH", "alpha": 0.05, "n_tests": int},
    "conclusion": str,                # **必须限定范围**
    "limitations": list[str],
}

Comparison = {
    "a": str, "b": str, "metric": str,
    "mean_a": float, "mean_b": float,
    "diff": float, "ci": (float, float),
    "p_raw": float, "p_adjusted": float,
    "effect_size": float,             # Cohen's dz
    "significant": bool,
}
```

**★ `baselines` 不能为空** —— 没有对照组的 `ResearchDesign` 应被拒绝构造。
这与项目的第二条原则（必须有对照组）是同一件事的代码化。

## 两个 Agent

### C1 方法设计 `METHOD`

| | 内容 |
|---|---|
| **作用** | 提出 / 比选技术路线 |
| **输入** | 研究问题 + 文献方法 |
| **输出** | `ResearchDesign` |
| **需模型** | ✅ 必须 |

#### 三个子部分

**① 候选路线生成** —— 至少给 2–3 条可行路线。

**为什么需要**：只给一条路线等于没做设计。
**"比选"是方法设计的实质** —— 没有比选，"我选了 M"就只是偏好。

**② 比选依据** —— 每条路线在「效果 / 成本 / 可验证性 / 风险」四个维度上的对比。

**为什么把"可验证性"单列**：这是本项目的立场 ——
一个无法验证的方法比一个效果稍差但能测的方法更糟。

**③ 基线与指标** —— 明确"跟谁比""用什么指标比"。

**为什么必须由 C1 定而不是 C2 定**：
基线选错，后面统计做得再对也没用。
**基线是设计决策，不是分析决策。**

---

### C2 实验设计与数据分析 `STATS`

| | 内容 |
|---|---|
| **作用** | 设计对照、跑统计检验、给结论 |
| **输入** | `ResearchDesign` + 实测数据 |
| **输出** | `StatsResult` |
| **需模型** | ❌ **统计部分完全确定性**（`copilot.stats` 已就绪） |

#### 已就绪的能力（可直接复用）

| 工具 | 位置 | 回答的问题 |
|---|---|---|
| `paired_bootstrap_diff_ci` | `copilot.stats` | 差值可能是多少 |
| `wilcoxon_test` | 同上 | 差异是否可能纯属偶然（非参数） |
| `paired_t_test` | 同上 | 同上（参数版，用于交叉验证） |
| `cohens_dz` | 同上 | 差异值不值得关心 |
| `benjamini_hochberg` | 同上 | 多重比较下该不该信 |

#### ★ 三条不能省的纪律

**① 必须用配对检验，不能用独立 CI 比较**

本项目在检索消融上**真的踩过这个坑**：
第一版用两个变体各自的 95% CI 比较，结论只能是「CI 重叠，无法断言」。
问题在于**浪费了最关键的信息 —— 它们跑的是同一批查询**。

改成配对检验后立刻检出真实差异：
`MRR +0.041 [+0.019,+0.066]，dz=+0.32，p(BH)=0.007`。

**② 必须做多重比较校正**

15 次检验不校正，即使毫无差别也期望出现约 0.75 个假阳性。
实测反例：trigram 融合的 Recall@1 未校正时 p=0.0455（会被判显著），
**BH 校正后 p=0.171 → 不显著**。

**不做校正就会多声称一项改进。**

**③ 必须同时报三个量**

| 量 | 回答 | 缺了会怎样 |
|---|---|---|
| p 值（校正后） | 是不是偶然 | 无法判断 |
| 差值 CI | 量级多大 | 显著但可能微不足道 |
| Cohen's dz | 值不值得关心 | 样本够大时微小差异也会显著 |

## 设计路线

| 步 | 内容 | 产出 | 状态 |
|---|---|---|---|
| 1 | `ResearchDesign` 模型 + 校验（`baselines` 非空） | `research/models.py` | 纯确定性 |
| 2 | **C2 分析器**（包 `copilot.stats`） | `research/analysis.py` | **最易先做** |
| 3 | 结论生成（限定范围的措辞） | `research/conclusion.py` | 规则 |
| 4 | C1 方法设计（模型，缺省给模板） | `research/design.py` | 需模型 |

**建议先做第 2 步**：纯确定性、能立刻复用现成统计代码、
而且它是"C1 的产出能不能用"的唯一判据。

## 验收标准

1. **`ResearchDesign` 没有 `baselines` 时构造失败**；
2. **所有比较都是配对检验**，`p_raw` 与 `p_adjusted` 同时给出；
3. **`corrections.n_tests` 与实际比较数一致**（不能挑着校正）；
4. **`conclusion` 必须带范围限定**（"在本语料上" / "在 60 篇样本下"），
   不允许出现无限定的普遍结论；
5. **`limitations` 非空**；
6. **同一份数据重跑得到同一结果**（固定种子）。

## 关键设计判断

| 判断 | 理由 |
|---|---|
| `baselines` 非空是构造约束 | 没有对照组的结论不成立，越早拦住越好 |
| 配对而非独立检验 | **实测**：独立 CI 会漏掉真实差异 |
| 强制 BH 校正 | **实测**：不校正会多声称一项改进 |
| 三个量一起报 | 单看 p 值会被"显著但无意义"骗 |
| 结论必须限定范围 | 样本量小的时候，无限定结论就是过度声称 |
| 不生成实验数据 | **红线**：编造数据是学术不端，不是工程问题 |

## 已知局限

| 局限 | 说明 |
|---|---|
| 不做功效分析 | "样本量够不够"只能给粗略经验值，不能给正式 power analysis |
| 不识别所有检验误用 | 例如嵌套数据用独立检验，需要模型判断数据结构 |
| 结论措辞靠模板 | 复杂结论仍需人工润色 |
| 只覆盖常见检验 | 方差分析 / 混合模型未实现；需要时按需加，不预先堆 |
| 数据质量无法验证 | 垃圾数据也能跑出"显著"，系统管不了 |

## ★ 一个落地的设计修正：`baselines` 不强制在构造时非空

设计文档写的是"没有基线就无法构造"。落地时改成 **`validate()` + 报告阻断项**：

| 方案 | 问题 |
|---|---|
| 构造时抛异常 | "无模型的骨架路径"彻底走不通 —— 骨架本来就没有真基线 |
| **validate + Finding** | 问题变成**用户看得见的报告项** |

约束没有放松，只是**从崩溃变成了阻断项**：
`ResearchDesign.validate()` 返回问题清单，阶段报告据此判为不可通过。

> 用户看到「❌ C1 缺少对照组」才会去补；抛异常他就只看到一堆栈。

## ★ 另一个实测修正：骨架设计的缺失必须是 ERROR

早期写法：

```python
severity = Severity.WARNING if design.skeleton else Severity.ERROR
```

结果：**7 个空字段的骨架设计被判为 ✅ 通过** ——
那等于告诉用户"你的研究设计合格了"。

**骨架不是完成品。** 改正：所有设计缺失**一律 ERROR**。

## C2 的实现

```python
for metric, observations in data.items():
    diff, lo, hi = paired_bootstrap_diff_ci(a, b)   # 差值 + CI
    _, p = wilcoxon_test(a, b)                      # 非参数配对检验
    dz = cohens_dz(a, b)                            # 效应量
# 全部指标算完后统一做 BH 校正，并以校正后 p 判显著
adjusted = benjamini_hochberg([c.p_raw for c in comparisons])
```

**三条纪律**（都来自本项目实测教训）：

1. **必须配对**（不能拿两组独立 CI 比较）；
2. **必须 BH 校正**（15 次检验期望 ~0.75 个假阳性）；
3. **三个量一起报**（p / 差值 CI / 效应量）。

**结论必须带范围限定**，代码里写死：

> 「该结论仅限本实验的样本与设置，不能直接外推到其他数据集。」

**没有有效对照组时**，C2 会额外报一条 `C2-NO-BASELINE` 级 ERROR ——
分析做得再对，没有基线结论也不成立。
